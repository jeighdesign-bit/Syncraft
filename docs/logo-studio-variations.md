# Dedicated logo variations

Implemented locally on 31 October 2026.

Clicking Variations opens a compact options popover; the preview toolbar no longer permanently displays style controls. One dropdown includes Auto and the existing 12-style catalog under Change style, alongside a small Create button. Auto is the default for each newly selected source and follows the accepted image's actual rendering, with the saved style label used only as context. The selected value sends an allowlisted `variationStyle`. Only Create starts generation; opening or choosing styles makes no provider calls. Escape, the close button, clicking outside or tabbing away dismisses the options. The creation sidebar style remains independent.

The server applies an explicit target after loading the signed source context, chooses structural directions for that target, and freezes the target plus source style in the new job. Target construction rules override old rendering instructions without overriding identity, meaningful motifs or exact text. The effective target is saved as the output's style for future variations. Wordmark requires saved brand text; Monogram uses saved initials or initials derived from the saved brand. Unavailable lettering choices are disabled in the selector, and missing text or unknown styles are rejected before reservation/billing on the server.

Variations now have their own prompt compiler, separate from Text, Image and Sketch creation and instruction editing. The selected saved logo is always the visual reference. The image model is instructed to inspect and preserve its identity anchors, important accessories and theme details, exact lettering, palette and rendering language, while changing both the main silhouette/construction and composition. Accepted edits take priority over older brief and color metadata.

`src/lib/logoVariations.mjs` defines four concrete directions for each of three families: characters, lettering, and symbols/enclosures. Character directions specify changes to viewing angle, gesture, pose and silhouette; lettering directions change letter construction and layout without replacing the exact text; symbol directions change shape relationships and negative space without inventing character anatomy. Non-character styles containing a character can still change its pose.

During the existing server revision transaction, each new option receives the next direction for its selected source. This prevents simultaneous options from receiving the same assignment. Failed attempts advance the direction too; directions cycle after four attempts. A frozen plan, compiled prompt, source context and seed are stored in the signed job. Replays return the existing request without planning, submission or billing again. Each output remains one image call at the existing 8-credit price, within the existing four-logo project quota; failures use existing refunds. No extra remote planner, hidden candidates, provider change or database migration is introduced.

Source metadata is read from signed project state, not from client-proposed style or brief fields. Edit and utility derivatives inherit missing settings, including exact monogram letters, through their source lineage. Their selected image remains the reference rather than the ancestor image. Public snapshots do not expose internal plans, compiled prompts or seeds.

Verification covers the dedicated prompt path across all 12 styles and three creation modes, distinct structural directions, concurrent reservation, exact source selection, source metadata tampering, accepted-edit precedence instructions, inherited initials/colors, replay protection, missing sources, pricing and refunds. Tests validate the instructions and service behavior, not visual output quality. A live image comparison is still needed to judge how reliably the image model meets the pose, composition and detail-preservation targets. No paid generation was performed during implementation.
