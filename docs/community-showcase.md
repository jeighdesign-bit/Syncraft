# Meet Our Community

Signed-in users open the **Submit Your Logo** modal in the workspace sidebar. The old `/community` URL redirects to the homepage with the modal open; it no longer renders a standalone submission page. Admins review at `/admin/community`, linked from the admin dashboard. No credits are charged.

The submission modal explains the upload, business details and approval steps. Its homepage preview shows only the logo in grayscale, without a card, business-name caption or visible URL. It previews the selected PNG or securely loads the owner's saved logo, including pending submissions; this preview does not publish the logo. Status copy explicitly distinguishes pending review from a live listing. The public marquee likewise uses bare logos linked to each business page.

Run `database/setup_community.sql` in the intended Supabase project before using the feature. It creates a service-only table with row-level security and a dedicated private `community-logos` storage bucket. Do not use expiring project storage or add public bucket policies. The setup was applied by the owner and verified against the local app on 9 November 2026.

Submissions require a business name, public HTTP(S) link, still transparent PNG up to 2 MB and explicit permission to display the logo. The client checks decoded alpha pixels; the server independently checks the actual format and alpha channel. Opaque PNGs, completely invisible PNGs, JPEGs, WebPs, SVGs and renamed non-PNG files are refused. Pixel checks establish that fully transparent and visible pixels coexist; admins still review whether the logo background is properly removed. The server limits decoded pixels to 16 megapixels, strips metadata and saves a transparent WebP preview up to 640 × 320. One submission is stored per account; reviewers also check for duplicate businesses across accounts.

Status flow: `pending` → `approved` or `changes_requested`. Resubmission resets any previous approval and generates a new revision. Owners may withdraw any listing; admins cannot republish a withdrawn listing. Reviews and withdrawals compare revisions so a stale action cannot approve a replacement image or undo a withdrawal. Admins should verify the business, relevance, link and permission before publishing. The public copy describes community membership without claiming verified usage, sponsorship, partnership or endorsement.

Only approved entries reach the public list. Public responses omit account IDs, storage paths, review notes and permission records. The logo endpoint also checks publication status before reading private storage; owners and admins can preview unpublished images with an authenticated request. List/image responses are not cached so subsequent requests respect withdrawal and moderation.

The homepage section sits below the hero/showcase and before How It Works. It has a small centered Meet Our Community label and a row of monochrome gray logos, without cards, visible business names, descriptions or a submission CTA. The section is hidden during loading, on failure and when there are no approved entries. One to five logos appear in a static row; six or more use a slow continuous loop. Hover pauses motion, keyboard focus restores normal scrolling, and a discreet pause/resume icon is available. Business names remain available in image alt text and link tooltips. Reduced-motion preferences show a static wrapping list with no duplicated logos. Both public and admin lists currently load at most 200 entries.

The temporary sample preview is removed. Both local development and production hide the entire section when no approved entries exist, including while loading or if the public list cannot be loaded. Only actual approved submissions appear in the showcase.

Validation: `node --test tests/community.test.mjs tests/communityShowcase.test.mjs`, the repository test suite and production build. Route tests exercise the real handlers with isolated database/storage doubles; they never publish fake businesses or alter customer accounts. Live checks confirm table access, private bucket configuration, denial of direct anonymous database reads, and unauthenticated API rejection.
